# AI 助手主动性提升方案

> 更新时间：2026-10-22 · 维护者：master agent
> 落地状态：**P0 已实现**（规则扫描 + 建议条 + 页面上下文注入 + 主动性提示词）

## 一、为什么现在「不主动」

现状是纯 request-response：用户打开助手 → 自己想到问题 → 提问 → 拿答案。四个结构性缺口：

| 缺口 | 现状 | 后果 |
|---|---|---|
| 没有触发源 | 只有「用户发消息」一种入口 | 系统知道周报要失败、大事儿没更新、待办没转化，却没人被提醒 |
| 没有建议载体 | 通知中心只做「提醒」，没有「下一步该做什么 + 一键去做」 | 用户看到提醒还得自己想怎么处理 |
| 没有上下文 | 发给模型的只有用户文字，不带所在页面/本周状态 | 回答泛泛，用户觉得「它不知道我在干什么」 |
| 没有主动性指令 | `SYSTEM_PROMPT` 只写「回答简洁专业」 | 模型即便发现异常也不会主动说 |

## 二、目标与边界

**目标**：让助手在正确时刻、用一句话，给出「现在最值得做的一件事」，并且点一下就能开始做。

**边界（护栏，先定死再谈能力）**：

1. **写操作永不自动执行**。所有主动行为止步于「建议 + 草稿」，转任务/发邮件/改状态必须用户显式确认（沿用 Jev 写门禁）。
2. **同类同周期只提一次**：`(user_id, dedupe_key)` 唯一，忽略即终态，不做二次骚扰。
3. **有上限**：首页同时最多 5 条、按分数排序；单用户 10 分钟内不重复扫描；7 天自动过期。
4. **可解释**：每条建议带 `body`（为什么现在提）+ `targetPath`（去哪做）+ `prompt`（点了做什么）。
5. **单一数据源故障降级**：某条规则查不通只是少一条建议，绝不影响面板其它内容。

## 三、主动性分级（决定后续能走多远）

| 级别 | 形态 | 用户成本 | 本项目状态 |
|---|---|---|---|
| L0 上下文感知 | 打开助手即带入当前页面/本周状态，回答贴合场景 | 0 点击 | ✅ 已实现（`pageContext` + 提示词） |
| L1 建议条 | 「3 个大事儿本周还没更新进展」+ 去做/忽略 | 1 点击 | ✅ 已实现（4 条规则） |
| L2 草稿预置 | 点「去做」直接进入已生成草稿的编辑态（不是空对话） | 1 点击 + 审阅 | ⏳ 下一步（需各业务页承接草稿态） |
| L3 主动推送 | 定时/事件触发，推企微或通知中心 | 0 点击 | ⏳ 复用 `WeeklyReportScheduler` + `WeComClient` |
| L4 白名单自动执行 | 低风险动作（如标记已读、生成草稿）自动完成并留审计 | 0 点击 | ❌ 暂不做，等前三级跑顺 |

## 四、触发源矩阵

| 触发 | 时机 | 适合的规则 | 状态 |
|---|---|---|---|
| 打开助手/工作台 | 拉取建议时按需扫描（10 分钟节流） | 全部 | ✅ |
| 定时 | 每日 08:50 / 周五 16:30 | 周报、待办、邮件 | ⏳ |
| 事件 | 邮件同步完成、会议纪要生成、周报生成失败 | 对应模块 | ⏳ |
| 状态差 | 上周同期对比（更新率、逾期数下降） | 管理视角建议 | ⏳ |

## 五、规则库（P0 已实现）

| kind | 判定 | 分数 | 建议动作 |
|---|---|---|---|
| `weekly_report` | 本周周报不存在 → 「还没有草稿」；`GENERATION_FAILED` → 「上次生成失败」并带错误原文 | 90 / 96 | 用 `weekly_report_facts` 取事实后按模版起草 |
| `key_matter_week` | 我负责、非已完成、本周未更新进展的大事儿的数量 | 70 + N | 逐项起草「进展/风险/需协调/下一步」 |
| `meeting_todos` | 近 7 天我主持的会议里 `DRAFT` 待办数量 | 60 + min(N,20) | 过一遍待办，给转任务/事项建议 |
| `email_digest` | 昨日摘要中 todos + risks 数量 | 55 + min(N,20) | 挑今天该处理的 3 条并提议转任务 |

规则写法约束：纯确定性查询，不引入额外模型调用（模型只用在用户点「去做」之后），保证 1 秒内出结果、可解释、可单测。

## 六、数据模型

`ai_proactive_suggestion`：`user_id / kind / dedupe_key(唯一) / title / body / prompt / target_path / score / status(NEW|DONE|DISMISSED) / created_at`。
`dedupe_key` 用「规则:周期」（如 `周报:2026-10-19`、`邮件:2026-10-21`），保证同周期只提一次；用户忽略后不再生成。

接口：
- `GET /api/ai-agent/proactive` → 扫描（节流）+ 返回前 5 条
- `POST /api/ai-agent/proactive/{id}/accept` → 用户点「去做」
- `POST /api/ai-agent/proactive/{id}/dismiss` → 用户点「忽略」

## 七、反馈闭环与指标

每次 accept/dismiss 都落终态，直接可算三个指标：

- **建议采纳率** = DONE / (DONE + DISMISSED)：低说明规则噪声大或文案不准。
- **触发覆盖率** = 有建议的用户 / 打开助手的用户：低说明规则太少。
- **打扰率** = DISMISSED / 总建议：> 50% 就该砍规则，而不是加规则。

后续可加权重表：按 kind × 用户历史采纳率调 `score`（简单频率衰减，不上模型）。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 建议变成新的骚扰源 | 唯一键去重 + 每用户上限 3~5 条 + 忽略即终态 + 打扰率监控 |
| 规则依赖的数据源变动 | 每条规则独立 try/catch，失败仅记日志；单测覆盖「数据源异常不影响其它规则」 |
| 建议与真实状态不同步 | 建议按需重算（每次打开重扫），`dedupe_key` 带周期，不缓存过期结论 |
| 模型擅自行动 | 主动行为只到 prompt 层；写工具仍走 Jev 门禁 + 用户确认 |
| 全量用户扫描拖慢系统 | 按需扫描 + 10 分钟节流；定时扫描只覆盖近 30 天活跃用户 |

## 十、不登录系统时如何触达（站外到达）

站内建议条只覆盖「已经打开系统的人」。真正的主动性必须能**找到人**，所以增加站外通道：

### 10.1 通道优先级

| 优先级 | 通道 | 现状 | 说明 |
|---|---|---|---|
| 1 | 企业微信应用消息（`WeComClient.pushText`） | ✅ 已接 | 复用邮件模块已配的 corpid/agentid/secret；收件人取 `email_wecom_mapping`（系统用户 → 企微 userid），未绑定则不推 |
| 2 | 企微机器人 CLI（`WeComCliClient`） | 有发送能力 | 无会话时无法主动发起，仅作为补充 |
| 3 | 邮件 | 有通道 | 暂不做自动邮件（避免变垃圾邮件），保留接口 |

### 10.2 推送节奏与文案（已实现）

- **工作日 08:50**（`ai.proactive.push-cron`，可用 `AI_PROACTIVE_PUSH_ENABLED=false` 关闭）扫描绑定企微的用户，逐人推送。
- **每人每天最多一条**：`ai_proactive_push(user_id, pushed_on)` 唯一键；发送失败也占位并记原因，避免重试风暴。
- 文案是「人话 + 三件事 + 一条直达链接」，不是系统通知口吻：

```
早上好，今天最值得先做的是：
1. 本周周报还没有草稿（周五 17:00 自动生成前可先起一版）
2. 2 个大事儿本周还没更新进展（皇家会员体系、飞鹤接口改造）

点开即可让我接着做，不用在系统里找：
https://<host>/ai-assistant?prefill=<首条建议的提示词>
```

- 链接落到 `/ai-assistant?prefill=…`（前端已支持），点开就是「带着任务来的对话」，不是空白聊天框。
- 助手页建议条上也提供「发到企业微信」，手动补发同样受每天一条限制。

### 10.3 一条消息的完整闭环

```
08:50 定时扫描 → 有高价值建议 → 企微消息（含深链）
   ↓ 用户在地铁上点开
/ai-assistant?prefill=… → 输入框已填好 → 回车 → 模型调工具 → 草稿出来
   ↓ 需要写操作（转任务/回邮件）
Jev 门禁 + 用户确认 → 执行 → 结果回对话，助手页显示本月用量
```

### 10.4 仍缺的一环：直接在企微里回复

真正「友好」的终点是**在企微里回一句话就能继续对话**，现状差一步：

| 方案 | 前置条件 | 工作量 | 建议 |
|---|---|---|---|
| 企微智能机器人回调（推荐） | 公网可达的回调地址 + Token/EncodingAESKey + 消息加解密 | 中（新增回调端点、验签解密、异步跑 agent、主动发消息回结果） | 下一阶段做 |
| CLI 轮询机器人会话 | 依赖 `wecom` CLI 是否开放「拉取会话消息」能力（当前能力清单里只有发送/待办/文档/搜索） | 低但不一定可行 | 先验证 CLI 能力再定 |

在回调落地前，站外只做「提醒 + 深链」，不做「假装能对话」——避免用户回复后没有回应，比不推更伤体验。

### 10.5 退订与静默

- 关闭定时：`AI_PROACTIVE_PUSH_ENABLED=false`。
- 个人级退订（待做 P2）：`email_wecom_mapping.enabled=0` 即停止站外推送；后续可加「只收周报周提醒」粒度。
- 静默时段天然被 cron 限定（仅工作日 08:50 一条）。
