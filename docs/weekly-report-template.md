# 周报固定模版（约定）

> 状态：已与负责人确认（2026-10-18）。周报 AI 生成的格式以此文为准。
> 对应实现：`WeeklyReportService#generationSystemPrompt`（提示词）、`#templateIssues`（生成后自检）、`#composeKpiSection`（KPI/商机拼装）。

## 1. 四个板块

沿用前端 `ReportDrawer` 的既有标题，不改：

| 字段 | 标题 |
|---|---|
| `coreWork` | 本周核心工作完成情况 |
| `kpiSection` | KPI相关情况 |
| `risks` | 问题/风险与解决办法 |
| `nextWeekPlan` | 下周工作计划 |
| `minutesMarkdown` | 周会纪要（本次未改，见 §6） |

## 2. 排版层级

纯文本，不用 Markdown：

```
一级标题：          顶格、以「：」结尾，名称固定
  二级分类：        缩进两个空格、以「：」结尾
  - 条目            以「- 」开头，一行一条
```

**本周无事项的分组，整组（含标题行）不出现。**

## 3. 各板块结构

### 本周核心工作完成情况

固定三个一级标题，顺序固定：

```
项目：
  皇家项目：
  - 京东VET抽奖积分同步异常（应为50、实际30000）：定位为活动配置问题。下一步：持续监控并清理多发积分
  飞鹤：
  - 京东自营新客报表：陆泽侧开发完毕，阻塞于微电云接口权限。下一步：推动接口开通并排期
产品：
  全渠道产品：
  - 开放平台 API & MCP：第一版代码 80%。下一步：完成联调评审
  海外产品：
  - Lifecycle AI EDM MVP：进度 85%。下一步：验收测试并准备上线
会员通：
  - 京东 omid 升级：完成切换，运行正常
```

| 一级标题 | 二级分类口径 |
|---|---|
| `项目：` | **客户交付项目，名称限定在白名单内**（见 §3.1）。每个子分类 1-3 条 |
| `产品：` | **只允许两个分类，名称固定**：`全渠道产品`、`海外产品`。云鹿全渠道产品 / CDP / MA / BI / AI 一律归「全渠道产品」；海外产品研发归「海外产品」。每个子分类 1-4 条 |
| `会员通：` | 不分子集，平铺条目 |

- 条目格式：`- 事项：结果或卡点。下一步：动作`
- 全篇最多 12 条，每条不超过 80 字
- **本段不再出现「商机：」**（商机已移入 KPI相关情况）

### 3.1 项目白名单（固定）

「项目：」的二级分类**只能**取白名单内的项目名。白名单来源按优先级：

1. **系统配置覆盖**：`weekly-report` 组、键 `core-work.project-groups`，值用逗号（`,` `，` `、` 都行）分隔，例如 `皇家项目,飞鹤`。
2. **项目主数据**（默认）：`project` 表里 `level=1` 且所属业务线名称含「云鹿」的项目——即「全渠道云鹿定制」「全渠道云鹿SAAS」（正好对应“合拍内的全渠道定制和 SAAS 项目”）。当前结果：皇家项目、飞鹤、佳贝艾特、海普诺凯、Speedo、黄天鹅、澳优、逢时。**新增客户只要在项目管理里建一级项目，周报白名单自动生效。**
3. 以上都读不到时回退代码内置常量 `DEFAULT_PROJECT_GROUPS`。

两道保障：

- 白名单会作为 `== 项目分组白名单 ==` 段落拼进模型输入，要求不得自建其它客户分组
- 生成后用 `normalizeGroups()` 做白名单校正：**白名单外的子分类行删掉、其下的条目保留**（不丢内容）；`产品：` 段只留两个固定分类，`会员通：` 段不接受子分类

> 校正只识别**缩进两个空格 + 以「：」结尾**的二级分类行（条目以「- 」开头，不受影响），所以模型若把子分类写成顶格，不会被删——宁可不纠正，也不能误删正文。

### KPI相关情况

固定两个一级标题，**两个都必须出现**：

```
KPI：
<系统算得出：业务线利润表原文>
<系统算不出：按生成指引 / 企微口径写，可写预估>

商机：
- 皇家 TM 处方签独立小程序：16.5 万，基本确定中标
- 库博全渠道：进入招投标阶段
```

- `KPI：` 的数字来源：`buildKpiSection(weekStart)` 有当月营收 → 以系统原文为准（数字必须准确）；没有当月营收 → 用模型按生成指引写的口径
- `商机：` 始终用模型输出（汇总企微、人为补充、生成指引与自动事实的 `opportunities`）
- 拼装逻辑见 `WeeklyReportService#composeKpiSection`

### 问题/风险与解决办法

固定两个一级标题，无事项的整组不出现：

```
项目：
  皇家项目：
  - 标品升级差异 4800 个、进度仅 15%，方案依赖外部协助 → 影响升级节奏。解决办法：拉张野协助出分类清单
会员通：
  - 京东 account 字段缺失致积分中断，存量补全依赖 xid 安全报备 → 延期即顺延开发。解决办法：京东批量补全工具 + 陆泽侧流水接口补全
```

- `项目：` 下用与 coreWork 相同的客户项目做二级分类；`会员通：` 平铺
- 条目格式：`- 风险：影响。解决办法：动作`，最多 5 条

### 下周工作计划

```
- 输出云鹿 OS 场景清单（复购/转段/加购未购）及 SaaS 版投入成本初算
- 完成 AI 助手订阅付费原型评审，出具 AI Agent 架构评审结论
```

- 只写 `- 工作项`，最多 6 条
- **不出现具体日期**（`10/23`、`11月13日`、`2026-10-23` 都不允许），需要表达时间用「下周」「月底前」「双十一后」

## 4. 生成后自检

`WeeklyReportService#templateIssues` 逐项检查，不合规则带上不合规项**重试一次**（仍不合规则保留首次结果并记 WARN）：

1. `coreWork` 至少有一个 `项目：/产品：/会员通：` 标题行
2. `coreWork` 不得出现 `商机：`
3. `kpiSection` 必须有 `KPI：` 和 `商机：`
4. `risks` 至少有一个 `项目：/会员通：` 标题行
5. `nextWeekPlan` 不得匹配 `\d{4}-\d{1,2}-\d{1,2}`、`\d{1,2}月\d{1,2}日`、`\d{1,2}/\d{1,2}`

白名单不在自检范围（非白名单子分类由 `normalizeGroups()` 直接校正，不用多花一次模型调用）。

## 5. 优先级

`生成指引`（用户提示词）> 本模版的分组/取舍规则 > 系统提示词其它条目。
模版本身（标题行、产品两个分类名、"下周计划不写日期"）是硬约束，生成指引也不能改。

## 6. 本次未改动（有意保留）

- **周会纪要 `minutesMarkdown`** 仍按原格式，末尾 `## 下周重点工作计划` 的 HTML 表格保留「预计时间」列（纪要需要时间点，只有周报正文去掉日期）。若要去掉，改提示词的纪要段落 + `WeeklyReportServiceTest#generationPromptRequiresWecomAndKeepsDetail` 即可。
- `kpiSection` 里 `商机：` 为空时，由模型按模版输出占位内容；若模型整段没按模版输出且系统 KPI 有数字，则只保留 `KPI：` 段。
