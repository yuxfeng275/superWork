## 实施顺序（对应目标任务）

1. **设计**（本目录）——评审通过后冻结，变更走 PR 并在文末记账。
2. **统一空间**：`ai_file` + `ObjectStore`（Local/MinIO）+ 三个投递入口 + 摘要入事实。
3. **编排内核**：`ai_run` / `ai_run_node` / `ai_invocation` / `ai_gate` + 幂等与未知结果 + 执行器插槽。
4. **夜间闭环**：SOP 快照 → 制品 → 晨报 → 次日审核 → 回写事实；运行面页面。
5. **上线与稳定**：241 部署、端到端演练、连续 5 个工作日指标。

## 三条不变量（任何实现都不得违反）

1. 编排主控只能是合拍（Java/MySQL），触发层不得决定多步流程。
2. 写权限只在合拍拦（`ai_invocation` + Jev 门禁），执行器的沙箱不算业务边界。
3. 执行器可替换（sidecar / dsh-acp / cli），换执行器不改业务代码与表结构。
