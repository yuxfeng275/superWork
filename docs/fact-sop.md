# 事实投递 SOP（不依赖开发，照着做就算交付）

> 更新时间：2026-11-07 · 读者：项目负责人 / 对接人 / 运维
> 相关：[fact-intake.md](fact-intake.md)（投什么、四个入口、可见性怎么选）、[privacy-policy.md](privacy-policy.md)（采什么不采什么）
> 本页只讲**动作**：什么时候做、怎么做、怎么算做完、做不成怎么办。

---

## ① 三条不可省的动作

| # | 动作 | 周期 | 谁做 | 一句话 |
| --- | --- | --- | --- | --- |
| 1 | 客户关键消息转进内部项目群 / 项目邮箱 | 每天，随手 | 对接人 | 客户嘴里说的，必须变成系统里有的 |
| 2 | 会议纪要在 24 小时内挂到项目 | 每次会后 | 项目负责人 | 录音先上传，转写和归属交给系统 |
| 3 | 周五清理「未归类」 | 每周五，10 分钟 | 项目负责人 | 没归属的邮件等于没投 |

其余一切（进度、缺陷、交付物、对账单）用哪个入口都行，见 [fact-intake.md](fact-intake.md) 的「四个入口」。

---

## ② 每天做什么（3 分钟）

1. **看三个数**：打开工作台，看顶部「今日已投 / 已隔离 / 未归类」。
   - 已投为 0 且今天确实有活 → 说明材料没进来，去做动作①。
   - 已隔离 > 0 → 菜单栏点开看是不是误杀（敏感文件被拦下是正常行为，文件还在本机）。
2. **过一遍今天的客户消息**：微信 / 电话 / 邮件里定下来的事，立刻做动作①（一条 30 秒）。
3. **今天有会就当场传录音**：散会 10 分钟内做动作②，别攒到周末。

不需要写周报式的总结，不需要整理格式——**原话比总结值钱**。

---

## ③ 每周做什么（10 分钟，建议周五下午）

1. **动作③ 清未归类**：工作台「未归类：N 封」→ 逐条指定项目，直到清零（详见 ④.3）。
2. **扫一眼本项目最近 20 条事实**：有没有明显不属于本项目的（归属选错）、有没有可见性选错的（内部成本投成了 `PROJECT`）。选错的改可见性或删掉重投。
3. **确认本机投递器还活着**：菜单栏「合拍·投递」→ 看「今日已投」不是 0、没有被误按成「暂停监听」。
4. **回复本周晨报**：晨报里被标「证据不足」的条目，指出来缺哪份材料，下次补投。

## ④ 谁负责（三段，各自只背自己的）

### 4.1 项目负责人 —— 对「事实层有没有料」负责

- 每周确认本项目事实层有新增；本周 0 新事实时按 ④.2 / ④.3 的排查顺序查。
- 每次会后 24 小时内把纪要挂上（动作②）。
- 周五清未归类（动作③），并处理归属错、可见性错的条目。
- 发现「客户侧关键结论只有口头版本」时，主动让对接人补（动作①）。

### 4.2 对接人（一线 / 客户侧）—— 对「客户原话有没有落系统」负责

- 客户在群里、电话里、现场说的关键结论，30 秒内转进内部项目群或项目邮箱（动作①）。
- 会后当场传录音，或把转写文本丢进投递箱。
- 判断标准一句话：**「如果我明天休假，同事看这条能不能接着干？」** 能，就投。

### 4.3 运维 —— 对「管道通不通」负责

- 项目邮箱别名 `inbox+<项目编码>@` 能收信、能路由到对应项目。
- 归档邮箱在正常收信（这是「未归类」和邮件事实的来源）。
- `PROJECT_CONTEXT_TOKEN` 有效（群机器人 / 值班脚本走这个）。
- 投递器分发（mac / Windows 打包、Windows 零安装走邮箱路径）。
- 保留期任务（默认 180 天清 `body`）在跑；脱敏规则随 `shared/privacy/sensitive-rules.json` 同步。
- 每周巡检指标：已投 / 已隔离 / 未归类 / 转写失败数。/ 数字异常时先看这几项，再找开发。

## ⑤ 三条动作逐条说明书

### 5.1 动作①：外部客户的关键消息转进内部项目群或项目邮箱

**为什么**：客户的口头结论没有任何系统记录，agent 读不到就等于没发生过。

**30 秒操作**（两条路，选顺手的）：

- **路 A（有企微）**：把客户原话粘进内部项目群，开头带 `#事实 #<项目编码>`，@ 群机器人。
- **路 B（Windows 零安装，浏览器就行）**：把客户那封邮件**转发**到 `inbox+<项目编码>@公司域名`，正文保留客户原话，别改成自己的总结。

**检查点（怎么算做完）**：群里有这条消息，且系统在 10 分钟内回帖「已入事实」；或邮箱投递后工作台「今日已投」+1，项目事实列表能看到这条。

**失败兜底（系统不可用）**：网页「项目详情 → 投递箱 → 说明」，把客户原话粘进去，可见性选 `PROJECT`；网页也进不去 → `bin/huji-put note "<项目>" "<原话>"`；全都不通 → 先记在项目群置顶的「待补投」清单，恢复后一次性补。

**本周 0 新事实时，看这里**：
1. 群里是不是只有「收到 / 好的 / 辛苦了」——这类本来就无信息量，不算漏投。
2. 转发时是不是漏了 `<项目编码>`——没有编码就进不了归属，会掉进「未归类」。
3. 客户是否只在**外部联系人单聊**里说过（系统不采这个，见 [privacy-policy.md](privacy-policy.md)），必须人工转。

---

### 5.2 动作②：当天的会议纪要在 24 小时内挂到项目

**为什么**：录音里的口头结论是最有信息量、也最容易丢的一类材料。

**30 秒操作**：会一散，打开合拍 → 该项目 → 会议 → **上传录音** → 确认「归属项目」下拉选的是本次项目 → 保存。
之后自动转写 → LLM 纪要（决议 / 风险 / 待办）→ 落事实，不用你写纪要。

**检查点（怎么算做完）**：24 小时内，项目「会议」列表出现该会议且状态为「已转写」，事实层能看到 ≥1 条决议或待办。

**失败兜底（录音质量差 / 转写失败 / 手机没录上）**：用投递箱的「说明」写三条就够——**决议**（定了什么）、**待办**（谁 / 什么时候）、**风险**（卡在哪）。一分钟写完，比补一整篇纪要便宜。

**本周 0 新事实时，看这里**：
1. 只有纯同步会、真的没形成决议 → 不硬凑，0 是正常值。
2. 录音是不是归属到别的项目了 → 去那个项目的事实列表捞回来改归属。
3. 转写失败数 > 0 → 找运维，别自己反复重传。

---

### 5.3 动作③：周五清理未归类

**为什么**：邮件没归属项目，事实层就少一块，夜里 agent 只能按碎片猜。

**30 秒操作**：打开工作台 → 顶部「**未归类：N 封**」→ 逐条点开 → 下拉选项目 → 确认。
**指定两次之后系统会自动学习**（同一发件人 / 同一关键词下次自动归属），所以第一周辛苦，第二周开始变少。

**检查点（怎么算做完）**：未归类清零，或只剩明确不归属任何项目的（全员通知、行政公告、招聘类）。

**失败兜底（N 很大 / 系统挂了）**：先按发件人批量指定（同一个客户一次性全选）；系统不可用时，把关键的几封转发到 `inbox+<项目编码>@` 先落事实，其余等恢复。

**本周 0 新事实时，看这里**：
1. 「未归类」一直是 0，但事实层也不涨 → **归档邮箱没在收信**，找运维（不是你的问题）。
2. 未归类清完了但事实还是 0 → 看这些邮件是不是本来就只是通知类，没有可执行的结论。
3. 项目邮箱别名 `inbox+<code>@` 的编码写错 → 外部来信会掉进未归类而不是进项目。

## ⑥ 一页检查表（贴在项目群置顶）

| 频次 | 动作 | 完成标志 | 谁查 |
| --- | --- | --- | --- |
| 每天 | 客户关键消息入系统 | 工作台「今日已投」≥ 1（有客户沟通的日子） | 对接人 |
| 每次会后 | 录音上传 + 归属 | 会议状态「已转写」，有 ≥1 条决议/待办 | 项目负责人 |
| 每周五 | 清未归类 | 「未归类」清零或只剩公告类 | 项目负责人 |
| 每周 | 管道巡检 | 已投 / 已隔离 / 未归类 / 转写失败 四项正常 | 运维 |

## ⑦ 这些动作和夜间 agent 的关系

夜里的 agent 只认 `project_fact` 这一张表：**表里没有的，对 agent 就等于没发生过。**

- **没证据就不派活**：候选必须挂 `source_ref` 才进夜间任务。事实层空 → 候选空 → 夜里空转，第二天晨报只有「暂无建议」。
- **证据越原始越好**：只有周报和邮件这类二手段材料时，产出的制品往往是通用套话；客户原话、对账 Excel、录音里的口头结论进了事实层，agent 才能落到具体版本、具体人。
- **投递花 1 分钟，评审省 30 分钟**：材料不全时，返工成本会挪到第二天的评审环节——那是最贵的地方。

所以本 SOP 的三条动作不是「行政要求」，是给夜里那台机器装眼睛。为什么投、投什么、四个入口怎么用、可见性怎么选，见 **[docs/fact-intake.md](fact-intake.md)**。
