# 致远 OA 开放平台「知识管理模块」功能规划

> 依据：致远开放平台 SeeyonAPI 8.2 文档
> - 事件清单：https://open.seeyoncloud.com/seeyonapi/8.2/event/72/
> - 事件使用说明：https://open.seeyoncloud.com/seeyonapi/1960/
> - 开放接口（REST）目录：https://open.seeyoncloud.com/seeyonapi/728/
> 梳理时间：2026-09-19。字段级实现前需以对应版本 JavaDoc（DocResourceBO / DocLibBO）和测试环境实测为准。

## 1. 这个页面提供的能力是什么

该页面是 SeeyonAPI 8.2 的 **Event 事件文档 · 知识管理模块**，共 **11 个文档生命周期事件**，全部为 **after（操作完成后）触发**。事件通过在 OA 内部署 Java 监听插件消费：

```java
// 同步监听
@ListenEvent(event = DocAddEvent.class)
public void onDocAdd(DocAddEvent event) { ... }

// 异步监听（推荐，避免阻塞 OA 主流程）
@ListenEvent(event = DocAddEvent.class, async = true)
public void onDocAddAsync(DocAddEvent event) { ... }
```

监听类注册为 Spring bean 后随插件包部署到 OA 服务端。

### 事件清单（原文档）

| # | 事件名称 | 事件对象 | 触发时机 | 可获取的关键数据 |
|---|---------|---------|---------|----------------|
| 1 | 文档新建监听 | DocAddEvent | after | createType、文档对象 DocResourceBO |
| 2 | 文档批量删除 | DocBatchCancelFavoriteEvent | after | 批量删除的文档 ID 集合 |
| 3 | 文档评论监听 | DocCommentEvent | after | 文档对象、评论人 memberId |
| 4 | 文档中心-删除文档 | DocDeleteEvent | after | sourcesID、appKey |
| 5 | 文档中心-收藏 | DocFavoriteEvent | after | sourceId |
| 6 | 文档中心-归档 | DocFiledEvent | after | sourcesID、docId、appKey |
| 7 | 文档评分监听 | DocGradeEvent | after | 文档对象、评分人 memberId |
| 8 | 文档中心-新增文档库 | DocLibAddEvent | after | 文档库信息 DocLibBO |
| 9 | 文档中心-删除文档库 | DocLibDeleteEvent | after | 文档库信息 DocLibBO |
| 10 | 文档中心-更新文档库 | DocLibUpdateEvent | after | 新文档库信息（旧文档库对象为预留方法，暂未使用） |
| 11 | 文档修改监听 | DocUpdateEvent | after | 文档对象 DocResourceBO |

## 2. 可以做哪些功能（功能清单）

按场景分组，优先级建议：P1 一期见效且低风险，P2 二期，P3 依赖 AI/推荐能力。

### A. 消息通知与提醒（P1）

| 编号 | 功能 | 触发事件 | 说明 |
|-----|------|---------|------|
| A1 | 新文档自动通知 | 文档新建 | 新文档入库后，按文档库/部门规则推送企业微信、钉钉或邮件给目标人群 |
| A2 | 文档变更通知 | 文档修改 | 文档被修改后通知收藏人、责任人或关注组 |
| A3 | 评论/评分提醒 | 文档评论、文档评分 | 有人评论或评分时通知文档 owner，缩短知识反馈链路 |
| A4 | 删除预警留痕 | 删除文档、批量删除 | 文档删除即时通知文档库管理员，附文档 ID 清单 |

### B. 知识库自动整理与同步（P1-P2）

| 编号 | 功能 | 触发事件 | 说明 |
|-----|------|---------|------|
| B1 | 搜索索引增量同步 | 新建、修改、删除、批量删除 | 增量推送外部检索引擎（ES 等），保证 OA 外搜索结果与 OA 一致 |
| B2 | 新文档自动打标/分类 | 文档新建 | 取文档对象调 AI 服务生成标签、摘要并回写或入标签库 |
| B3 | 归档联动 | 文档归档 | 归档完成后自动向档案系统/归档库登记，替代人工台账 |
| B4 | 文档库目录同步 | 文档库新增/更新/删除 | 把文档库结构变化同步到下游系统（知识中台、网盘、门户） |
| B5 | 外部知识中台单向同步 | 新建、修改、删除 | 以事件为触发源，向集团知识中台做增量同步 |

### C. 统计与知识画像（P2）

| 编号 | 功能 | 触发事件 | 说明 |
|-----|------|---------|------|
| C1 | 知识贡献统计 | 新建、修改 | 按人/部门累计产出，形成贡献榜与部门知识资产报表 |
| C2 | 热门知识排行 | 收藏、评论、评分 | 聚合行为数据生成热门文档榜，供门户栏目展示 |
| C3 | 知识质量看板 | 评分、评论 | 评分分布、评论量、归档量等指标看板，识别低质/高价值知识 |
| C4 | 个人知识画像 | 收藏、评论、评分 | 沉淀成员兴趣与专长标签，支撑专家定位 |

### D. 审计与合规（P2）

| 编号 | 功能 | 触发事件 | 说明 |
|-----|------|---------|------|
| D1 | 删除行为审计 | 删除文档、批量删除 | 删除操作实时写入独立审计库，保留谁在何时删除了哪些文档 ID |
| D2 | 归档合规台账 | 文档归档 | 归档事件自动生成台账记录，支撑合规检查 |

### E. 智能化应用（P3）

| 编号 | 功能 | 触发事件 | 说明 |
|-----|------|---------|------|
| E1 | 知识问答语料沉淀 | 新建、修改、评论 | 新文档与高质量问答进入语料库，供知识问答机器人使用 |
| E2 | 个性化知识推荐 | 收藏、评分、评论 | 行为数据喂给推荐服务，在门户做个性化推荐 |

## 3. 实施方案（建议架构）

```
致远 OA（V8.2）
  └─ 事件监听插件（Java，@ListenEvent，一律 async + try/catch）
       └─ 事件转发服务（去重、幂等、重试、白名单过滤）
            ├─ 消息通道：企业微信 / 钉钉 / 邮件
            ├─ 检索/知识中台：索引与数据增量同步
            ├─ 数据仓库 / 看板：行为统计与画像
            └─ AI 服务：打标、摘要、推荐、语料
```

关键设计原则：

1. **监听一律异步**：所有消费端逻辑放在 async 监听 + 外部队列，禁止在同步监听里做远程调用，避免拖慢或阻塞 OA 主流程。
2. **幂等与重试**：以 docId + 更新时间（或版本）做幂等键，转发失败进入重试队列，防止下游重复/丢失。
3. **白名单过滤**：按文档库配置同步范围，避免全库噪声。
4. **事件只做触发，详情走 REST**：收藏/删除类事件只带 sourceId，需要配合开放接口中的「文档服务管理」等 REST 接口反查详情；回写通知可用「消息服务管理」。
5. **发布方式**：监听插件随 OA 插件包部署，需要 OA 侧发布窗口与回归验证；是否停机取决于客户现场的插件部署方式。

### 分期建议

- **一期（P1）**：A1-A4 + B1，先跑通「插件 → 转发服务 → 1-2 个消费端」，验证事件稳定性。
- **二期（P2）**：B2-B5 + C 组 + D 组，扩展数据面与统计面。
- **三期（P3）**：E 组智能化应用，在数据积累后启动。

### 待办事项与报表补充

**待办事项：有完整接口，建议纳入一期。**

- 查询待办数量：`POST /seeyon/rest/affair/pending/count`，可按人员和应用类型返回协同、公文、会议等待办数量。
- 查询待办列表：`GET /seeyon/rest/affairs/pending`，支持按人员和应用类型查询；也可按人员编码调用 `/seeyon/rest/affairs/pending/code/{memberCode}`。
- 事项服务支持分页，并提供待办、已办、待发、已发、在办、督办、跟踪等事项查询能力。
- 对外同步待办状态：V8.2 以上优先监听 `ExtIntegrationExtendEvent` 统一待办事件，一次覆盖待办、已办、终止、回退、撤销等状态变化，并支持协同、公文、会议、新闻、公告、调查、讨论模块。
- 待办对象可提供标题、状态/子状态、接收时间、完成时间、期限、重要程度、催办次数以及 PC/移动端跳转地址，适合做统一待办中心。

**报表：当前公开 SeeyonAPI 文档未发现独立的报表服务接口。**

- `事项服务`可以提供流程事项明细和状态数据，可作为流程效率、超期、待办量等报表的数据来源。
- `CAP4表单应用`和 `cap4动态接口`更偏表单数据访问、保存前后 Hook，不等同于内置报表设计、报表查询或导出 API。
- 如果要做外部 BI/管理驾驶舱，建议通过事项 REST、CAP4 业务数据接口或受控数据同步进入报表库，再由 BI/报表引擎生成图表。
- 如果要直接读取 OA 内置报表、调用报表参数、导出 Excel/PDF，需要客户现场版本、产品授权和实际菜单/接口文档进一步确认，不能仅凭当前 SeeyonAPI 目录承诺。

## 4. 边界与风险（需在方案评审时明确）

1. **全部为 after 事件，不能拦截或阻断操作**：如需「保存前校验」「禁止删除」类控制，本页事件做不到，要走表单校验或另找 before 类事件/其他机制。
2. **「文档批量删除」的类名是 DocBatchCancelFavoriteEvent**：标题与类名语义不一致（类名像"批量取消收藏"），实际语义必须在测试环境实测确认后再排期。
3. **文档库更新事件拿不到旧值**：DocLibUpdateEvent 的 getOlddoclib 是"暂未使用，预留方法"，如需变更对比，要自行留存全量快照比对。
4. **收藏/删除/归档事件只有 ID**：详情需配合 REST 文档服务接口反查，需评估接口权限与频率。
5. **插件部署有运行风险**：需要 OA 侧发布窗口；异常处理不当会影响主流程，务必 async + 全量捕获，并准备回滚包。
6. **版本差异**：以上以 SeeyonAPI 8.2 文档为准；客户 OA 版本不同（V9/V10/V11）事件清单与字段可能有差异，实施前按现场版本重新核对。

## 5. 可扩展范围

同一 Event 机制在 8.2 文档中共覆盖 21 个模块：讨论、公告、任务管理、协同、**知识管理**、公文、调查、会议、新闻、综合办公、组织模型、计划、项目管理、督办、小智、全局、日程、CIP 集成、cap4、表单、门户。知识管理跑通后，通知/同步/统计框架可直接复用到协同审批、公文流转、会议纪要等场景。

REST 开放接口另提供组织、BPM、消息服务、文档服务、会议、计划、日程、任务、公文、HR、附件、统一待办、CAP4 表单等 20+ 类服务接口，可作为事件方案的反查与回写通道。
