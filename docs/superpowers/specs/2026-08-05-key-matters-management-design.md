# 大事儿管理设计

> 访问契约取代说明：2026-08-20 的《大事儿参与人及负责人周进度反馈设计》已取代
> 本文的固定 `admin/yufeng` 访问白名单、路由/API 访问边界及其验收表述。该取代仅限
> 访问与授权；本文的数据模型、事项/周进度行为、页面交互和其他非访问设计继续有效。

## 目标

为 BU 负责人提供一个独立的重点事项台账，用于持续跟踪负责人、计划时间、
完成进度和每周问题，并通过系统内周会模式直接完成周度汇报。

该功能不是现有 `issue` 问题事项的扩展。`issue` 仍服务于需求和任务中的问题、
风险、变更；“大事儿”是 BU 级管理对象，拥有独立生命周期和访问边界。

## 权限边界（访问契约已被 2026-08-20 设计取代）

以下固定白名单规则仅记录初始设计，不再作为当前访问或安全契约；当前规则以
2026-08-20 的参与人/负责人关系加数据库权限模型为准。

- 仅用户名 `admin` 和 `yufeng` 可以看到导航、访问页面和调用接口。
- 前端路由守卫和菜单过滤用于改善体验，后端用户名校验是最终安全边界。
- 负责人可以选择任意启用中的本地用户，不要求负责人本人拥有页面权限。
- 创建人和每周更新人必须取 JWT 中的 `userId`，不接受客户端传入。

未经授权的已登录用户访问 `/api/key-matters/**` 时返回 HTTP 403；未登录请求
由现有认证链返回 HTTP 401。

## 数据模型

### `bu_key_matter`

| 字段 | 规则 |
| --- | --- |
| `id` | 自增主键 |
| `title` | 必填，最多 200 字 |
| `description` | 可选，事项背景或目标 |
| `project_id` | 可选，关联一个本地项目；项目删除时置空 |
| `owner_id` | 必填，关联启用中的本地用户 |
| `priority` | `P0`、`P1`、`P2`，默认 `P1` |
| `status` | `未开始`、`推进中`、`有风险`、`已阻塞`、`已完成`、`已暂停` |
| `progress` | 0 到 100 的整数 |
| `start_date` | 必填 |
| `planned_completion_date` | 必填，不早于开始日期 |
| `completed_at` | 状态首次变为 `已完成` 时自动写入；离开完成状态时清空 |
| `sort_order` | 默认 0，用于负责人手工排序 |
| `created_by` | JWT 用户 ID |
| `created_at` / `updated_at` | 服务端时间 |

完成状态强制进度为 100。非完成状态不允许进度为 100，避免状态和进度互相
矛盾。删除大事儿时级联删除其周进展。

### `bu_key_matter_weekly_update`

| 字段 | 规则 |
| --- | --- |
| `id` | 自增主键 |
| `key_matter_id` | 必填，关联大事儿 |
| `week_start_date` | 必填，必须为周一 |
| `status` | 必填，保存当周状态快照 |
| `progress` | 必填，0 到 100 |
| `progress_summary` | 必填，本周进展摘要 |
| `issues` | 可选，问题与风险 |
| `next_week_plan` | 可选，下周计划 |
| `support_needed` | 可选，需协调或决策事项 |
| `created_by` | JWT 用户 ID |
| `created_at` / `updated_at` | 服务端时间 |

同一大事儿同一周只保留一条记录，数据库唯一键为
`(key_matter_id, week_start_date)`。重复提交执行更新而不是新增。保存周进展后，
当该记录是时间上最新的一周时，主事项的状态和当前进度同步为周进展中的值，
并按完成状态规则更新 `completed_at`；补录或修改更早周次不会回退当前状态。
删除周进展只删除历史记录，不自动改写主事项当前状态。

## API

所有接口前缀为 `/api/key-matters`，返回值继续使用项目现有 `Result<T>` 包装。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/key-matters` | 查询台账，支持状态、优先级、负责人、项目和关键词筛选 |
| `GET` | `/api/key-matters/{id}` | 查询事项及全部周进展 |
| `POST` | `/api/key-matters` | 创建事项 |
| `PUT` | `/api/key-matters/{id}` | 编辑事项 |
| `DELETE` | `/api/key-matters/{id}` | 删除事项及周进展 |
| `PUT` | `/api/key-matters/{id}/weekly-updates/{weekStartDate}` | 新增或更新指定周进展 |
| `DELETE` | `/api/key-matters/{id}/weekly-updates/{weekStartDate}` | 删除指定周进展 |
| `GET` | `/api/key-matters/meeting?weekStartDate=YYYY-MM-DD` | 获取周会模式数据 |

列表返回负责人姓名、项目名称、最新周进展、是否逾期和本周是否已更新，避免前端
逐条补充查询。周会接口默认使用当前周周一，返回所有未完成事项，以及本周完成的
事项；排序为 `P0 -> P1 -> P2`、有风险/阻塞优先、`sort_order`、计划完成日期。

## 页面与交互

在工作台导航增加“大事儿管理”，路由为 `/key-matters`。页面保持现有后台系统的
紧凑工作台风格，不使用营销式首屏或卡片墙。

### 台账视图

- 顶部展示总数、推进中、有风险/阻塞、本周未更新四个摘要指标。
- 筛选区提供关键词、状态、优先级、负责人和项目筛选。
- 主体使用可扫描表格，列为优先级、事项、负责人、进度、状态、计划完成、
  最新周进展和操作。
- 进度使用稳定宽度的进度条；逾期日期和风险状态使用语义色。
- 新增和编辑使用抽屉；删除必须二次确认。
- 行点击打开详情抽屉，展示基础信息和按周倒序的进展时间线。
- 详情内提供“更新本周进展”操作；同一周再次保存即覆盖本周记录。

### 周会模式

- 页面顶部使用“台账 / 周会模式”标签切换，不新增第二个导航入口。
- 周会模式按优先级和风险排序，以全宽条目逐项展示事项名称、负责人、状态、
  进度、计划完成时间，以及本周进展、问题风险、下周计划、需协调/决策事项。
- 缺少本周更新的事项明确显示“本周待更新”，并可直接打开周进展编辑器。
- 已完成事项仅在完成所在周展示，避免历史完成项长期占用周会页面。
- 桌面可直接投屏；移动端纵向排列，页面本身不产生横向滚动。

## 状态与异常处理

- 列表、详情和周会数据分别提供加载、空数据和请求失败状态。
- 无效负责人、无效项目、非法日期、非法状态、非法进度返回 HTTP 400 和明确中文
  消息；不存在的事项返回 HTTP 404。
- 并发更新以最后一次保存为准，`updated_at` 用于展示最近更新时间；当前版本不引入
  乐观锁和审批流程。
- 删除操作放在事务中，外键保证周进展不会残留。

## 明确不做

- 不导出 Markdown、Word 或 PPT。
- 不做消息提醒、企微通知或自动催办。
- 不关联云效工作项、需求或任务，只可选关联一个本地项目。
- 不支持多人协同编辑和评论；事项 CRUD 仍只有具备管理组合条件的 `admin/yufeng` 维护，读取和负责人周进度反馈按 2026-08-20 动态访问契约执行。
