# 大事儿完成后停止周度更新设计

## 目标

当大事儿状态进入 `已完成` 后，系统不再要求或允许为其新增周度更新，并从所有“待更新”统计、提醒和补报入口中排除。已存在的历史周报继续可查、可修正；如事项需要继续推进，必须先重新打开事项。

本次仅调整大事儿周度更新规则，不修改需求、任务、缺陷或其他页面。

## 业务规则

### 完成与更新资格

- `status = 已完成` 的事项不需要后续周度更新。
- 完成事项不计入本周待更新数量、未更新提醒或周会补报数量。
- 完成事项不展示“更新周报”“更新周进展”等新增入口。
- 事项通过周报提交 `已完成 + 100%` 时，该条周报作为完成当周的最后记录并正常保存。
- 事项通过事项编辑直接改为 `已完成` 时，不要求补建完成周报。

### 历史数据

- 已完成事项的历史周报继续展示。
- 已存在的历史周报允许编辑，以修正文案、风险、支持事项等历史信息。
- 编辑已完成事项的历史周报不得同步改变事项当前状态、当前进度或 `completedAt`。
- 删除历史周报保持现有语义：只删除周报，不重算事项当前状态。
- 已完成事项禁止为任意不存在周报的周次新增记录，包括补录完成前的空白周次。

### 重新打开

- 如果已完成事项需要继续推进，用户必须先在事项编辑中将状态改为非 `已完成`，并将进度调整到 `0-99`。
- 重新打开后，事项恢复新增周报资格，并重新参与待更新统计。
- 周报编辑本身不能承担“重新打开事项”的职责。

## 前端行为

### 登记列表

- 已完成行不显示“更新周报”操作。
- 已完成行显示稳定的完成状态，不显示“本周待更新”。
- `本周待更新` 只统计非完成且当前周没有周报的事项。
- `已更新` 统计不把“已完成但本周无周报”误当成缺失；其口径保持为实际存在当前周周报的事项数。

### 详情抽屉

- 已完成事项隐藏顶部“更新周进展”按钮。
- 历史时间线继续显示。
- 已存在历史周报的编辑入口继续可用。
- 历史周报编辑保存后仍保持事项为已完成。

### 周会与演示模式

- 查询继续包含所有未完成事项，以及在所选周内完成的事项。
- 在所选周完成的事项以只读完成摘要展示。
- 如果完成事项在该周没有周报，展示 `本周已完成，无需更新`，不显示内联补报表单。
- 完成周之后的周会不再返回该事项。
- 周会的待更新数量和补报导航只考虑非完成事项。

## 后端契约

### 周报写入

`PUT /api/key-matters/{id}/weekly-updates/{weekStartDate}` 在读取事项和目标周现有记录后执行以下判断：

| 事项状态 | 目标周已有记录 | 行为 |
| --- | --- | --- |
| 非已完成 | 否 | 创建周报，并按现有规则同步最新事项状态 |
| 非已完成 | 是 | 更新周报，并按现有规则同步最新事项状态 |
| 已完成 | 否 | 拒绝，消息 `已完成事项无需新增周进展` |
| 已完成 | 是 | 允许修正周报，但不更新事项状态、进度或完成时间 |

完成状态判断以后端数据库中的事项当前状态为准，不能依赖前端隐藏按钮。`BuKeyMatterMapper` 增加 `selectByIdForUpdate(Long id)`，写入事务先通过 `SELECT ... FOR UPDATE` 锁定事项行，再读取目标周现有记录并执行上述分支。事项编辑和周报写入因此按同一事项串行化，不新增数据库迁移。

### 周会查询

`GET /api/key-matters/meeting?weekStartDate=YYYY-MM-DD` 保持现有纳入规则：

- 非完成事项始终纳入。
- `completedAt` 落在所选周周一至周日内的完成事项纳入。
- 其他完成事项不纳入。

返回的 `currentWeekUpdated` 仍仅表示所选周是否确实存在周报，不表示该事项是否需要周报。前端使用事项状态判断“无需更新”。

## 错误与并发

- 后端在写入事务内锁定事项行后决定创建或更新，直接 API 调用不能绕过完成状态限制。
- 事项编辑也使用同一行锁读取路径，确保事项完成与周报新增不会交叉提交。
- 若用户打开周报表单后，其他人将事项完成，保存时后端返回 `已完成事项无需新增周进展`；前端关闭新增流程、刷新事项并展示后端原因。
- 已存在历史周报的编辑请求可继续成功，但不得触发事项重新打开。
- 如事项不存在，沿用现有资源不存在错误。
- 周一日期校验、权限和用户名白名单保持现有契约。

## 测试与验收

### 后端

- 已完成事项对不存在周报的周次执行 upsert，返回 `已完成事项无需新增周进展`，且不插入数据。
- 已完成事项编辑已有历史周报成功，且事项状态、进度、`completedAt` 不变。
- 并发完成与新增周报使用事项行锁串行化，后到的新增请求按最新完成状态被拒绝。
- 非完成事项提交完成周报成功，保存完成记录并将事项同步为已完成。
- 重新打开事项后可以新增周报。
- 周会包含完成当周事项，后续周不包含。

### 前端

- 登记列表的已完成事项没有新增周报按钮，也不显示待更新状态。
- 已完成事项不计入待更新统计。
- 详情抽屉隐藏新增入口，但历史周报编辑入口可用。
- 周会对无完成周报的完成事项显示 `本周已完成，无需更新`，不渲染补报表单。
- 并发完成导致保存失败时，页面刷新为已完成状态并展示明确提示。

## 发布与回滚

- 不需要数据库迁移。
- 先发布后端限制和测试，再发布前端入口与统计调整。
- 回滚仅需恢复前后端版本，不涉及数据回滚。
- 发布后使用一个已完成且本周无周报的事项验证列表、详情、周会和直接 API 写入行为。
