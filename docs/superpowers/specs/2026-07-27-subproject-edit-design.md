# 子项目编辑功能设计

## 背景

项目管理页面已经支持主项目编辑，子项目目前以标签形式展示，点击仅能打开详情，缺少直接编辑入口。后端已有 `PUT /api/projects/{id}`，但更新项目名称时存在完整路径未同步的问题。

## 交互设计

- 子项目继续使用现有紧凑标签展示，名称区域点击后打开详情抽屉。
- 标签右侧增加独立的铅笔图标按钮，悬停提示“编辑子项目”。
- 点击编辑按钮复用现有项目编辑弹窗，预填业务线、父项目、名称、编码、负责人和状态。
- 保存成功后关闭弹窗并刷新项目树；保存失败时保留弹窗和输入内容，显示错误提示。
- 编辑按钮提供明确的 `aria-label` 和可见焦点状态，不影响子项目名称的点击行为。

## 数据行为

- 前端继续调用 `api.updateProject(id, payload)`，不新增 API。
- 后端更新项目名称前记录旧名称；名称变化时重新计算当前项目的 `fullPath`。
- 主项目改名时继续级联更新所有子项目路径；子项目改名时仅更新自身路径。
- 本次不支持通过编辑弹窗改变项目层级或移动父项目，保持现有后端语义。

## 验收标准

1. 每个子项目标签都有可键盘访问的编辑图标。
2. 点击编辑图标不会打开详情抽屉，而是打开“编辑项目”弹窗。
3. 弹窗展示子项目现有值，保存发送正确的项目 ID 和表单数据。
4. 子项目改名后，数据库中的 `name` 和 `fullPath` 同步更新。
5. 现有主项目编辑、子项目详情和新增子项目功能不回归。

## 测试

- Playwright：模拟项目树，点击子项目编辑按钮，修改名称并断言 `PUT /api/projects/{id}` 请求。
- JUnit：更新子项目名称后断言 `fullPath` 使用父项目路径重新计算。
- 完成后运行前端构建、相关 Playwright 测试、后端单测，并在真实页面执行一次编辑流程。
