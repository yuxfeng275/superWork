# 隐私政策（一页人读版）

> 更新时间：2026-11-07 · 适用：合拍·投递（macOS 菜单栏）、`bin/huji-put`、Windows 工具、项目邮箱、企微项目群、会议纪要
> 相关：[fact-intake.md](fact-intake.md)（投什么、怎么选可见性）、[fact-sop.md](fact-sop.md)（每天 / 每周怎么操作）
> 规则单一口径：`shared/privacy/sensitive-rules.json`（本地护栏与服务端脱敏读同一份）

**一句话**：合拍只收「你主动交给它的工作材料」，不收你在电脑上做的一切。

---

## ① 采什么

| 来源 | 具体范围 |
| --- | --- |
| 工作目录里的文件 | 你放进配置目录的文件。默认 `~/Documents/合拍`、`~/Downloads/合拍`（含子目录）；其它目录只有你自己在配置窗口里加进去才会被监听 |
| 公司工作邮箱 | 你的公司邮箱账号，以及项目邮箱别名 `inbox+<项目编码>@`（外部客户直接发进来即入事实） |
| 公司内部企微项目群 | 你在的内部项目群，机器人/转发进来的消息 |
| 会议纪要 | 你上传的录音 → 自动转写 → 纪要（决议 / 风险 / 待办），归属到项目后入事实 |

采集**不静默**：配置窗口里逐条列出「正在监听哪些目录」，菜单栏里能看到「今日已投 N · 已隔离 M」。

---

## ② 不采什么（逐条）

| 不采 | 怎么保证 |
| --- | --- |
| **不采全盘** | 只监听配置里明确列出的目录，不做整盘扫描、不遍历未配置的目录 |
| **不采屏幕** | 没有截屏 / 录屏能力，不申请屏幕录制权限 |
| **不采键盘** | 不做键盘记录，不注册全局输入监听 |
| **不采剪贴板** | 不读剪贴板；粘贴聊天记录只有你亲手粘进「投递箱」才会进来 |
| **不采浏览器历史** | 不读浏览器数据目录，不采集访问记录 |
| **不采私人邮箱** | 只接公司工作邮箱；个人邮箱账号一律不配置、不接入 |
| **不采私人微信** | 微信个人号不接入。要进事实的客户消息由你手动转（见 [fact-sop.md](fact-sop.md) 动作①） |
| **不采外部联系人单聊** | 客户 / 供应商的单聊不自动抓取，只在内部项目群或项目邮箱里留痕 |

采集范围**一次配置、随时可查**：想收窄就把目录从配置里删掉，存盘立即生效，已投的历史事实可在网页端逐条删除。

## ③ 本地过滤：命中就不发请求

投递前，本机按 `shared/privacy/sensitive-rules.json` 逐文件判定五类命中：

| 判定类别 | 例子（口径以实现为准） |
| --- | --- |
| 文件名关键词 | 工资、薪资、绩效、身份证、合同底价、报价底价、离职… |
| 扩展名 | 密钥 / 凭据类扩展名、可执行文件 |
| 密钥文件名 | `.env`、`id_rsa`、`*.pem`、`*.p12`、`credentials*` 这类凭据文件 |
| 大小 | 超过单文件上限的超大文件 |
| 临时文件 | `.DS_Store`、隐藏文件、`.part` / `.crdownload` / `.swp` / `~` 等未完成文件 |

命中即**移到本地「已隔离」目录**：不上传、不建事实、不落日志正文，只留一条本地计数。
菜单栏「已隔离 N」可点开看文件名并恢复或彻底删除——**服务端全程收不到这个文件**。

## ④ 服务端：入库前脱敏，原文不留

- **脱敏发生在写库之前**：手机号、身份证号、银行卡号、邮箱地址、薪资金额一律替换为占位符（如 `<PHONE>`、`<ID_CARD>`、`<BANK_CARD>`、`<EMAIL>`、`<SALARY>`）。
- **原文不入库**：附件正文不存原始文本，只存脱敏后的正文与摘要；上传的原始文件按投递记录管理，不进可检索的事实正文。
- **保留期默认 180 天**：到期只清 `body`（原文），**保留摘要与来源引用**（`source_ref` / 项目归属 / `actor_id` / 时间），保证「谁在什么时候投了什么」可追溯，也不再留敏感全文。
- **可追溯到人**：每条事实带 `actor_id` 与投递时间。

## ⑤ 可见性：默认值就够安全

| 情形 | 默认口径 |
| --- | --- |
| 普通投递（文件 / 说明 / 聊天 / 会议 / 邮件） | `PROJECT` |
| **文件名命中敏感关键词**的投递 | `OWNER`（仅自己可见，别人和部分 agent 场景读不到） |
| **外部来信**（外部客户 / 外部地址发来的邮件） | `PRIVATE_COMPANY`（仅本公司可见） |

三个口径的取值与什么时候该手动改，见 [fact-intake.md](fact-intake.md) 的「可见性怎么选」。拿不准时一句话：**客户看得到会不会尴尬？会 → `PRIVATE_COMPANY`。**

---

## ⑥ 谁能看到

| 口径 | 谁看得到 |
| --- | --- |
| `PROJECT` | 该项目的项目成员（含客户侧参与人） |
| `PRIVATE_COMPANY` | 只有本公司成员（管理角色 / 项目负责人 / 项目成员 / 持 `project:manage` 的人） |
| `OWNER` | 只有投递人本人 |

> **已知边界（不藏着）**：成员表目前没有「本公司 / 合作方」标记，合作方参与人一旦被加进项目成员，`PRIVATE_COMPANY` 会被一并放行。
> 补上内外标记之前，合作方隔离靠「合作方不进成员表」。要投内部成本、毛利、报价底价时，除了选 `PRIVATE_COMPANY`，也别把合作方拉进成员表。

## ⑦ 你手里的开关

- **一键暂停**：菜单栏「合拍·投递」→「暂停监听」，立即停，不再读任何目录；恢复点「恢复监听」。
- **卸载**：退出 app，删 `~/Library/LaunchAgents/com.bu.hepai.delivery.plist`（或 `scripts/install-launch-agent.sh --uninstall`），再把「合拍投递.app」丢进废纸篓。
- **删自己的投递**：网页端随时可删，删掉即从事实层消失。
- **查自己的采集范围**：配置窗口列出全部监听目录；菜单栏显示「今日已投 / 已隔离」数量。
- **本机残留**：密码只进系统钥匙串（不写盘）；配置 `~/.hepai-delivery.json` 不含密码，权限 `0600`。

## ⑧ 审计与承诺

- **可审计**：所有投递带 `actor_id` 与时间，可追溯到具体的人、具体的入口。
- **明确承诺**：
  - **不用于绩效评估**——事实层的用途是给夜间 agent 提供工作证据，不是考核依据。
  - **不做员工监控**——不统计在线时长、不做行为画像、不因「投得少」触发任何管理动作；投递量不作为评价指标。
- 例外只有一种：安全事件（如凭据误投）按公司既有信息安全流程处理，且走人工确认，不自动化。

有疑问或发现越界采集，直接找项目负责人或运维，按上表逐条核对采集范围。
