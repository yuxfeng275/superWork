# 迁移路线与验收

## 1. 阶段计划

| 阶段 | 目标 | 主要输出 | 退出条件 |
|---|---|---|---|
| P0 | 功能基线和契约冻结 | 路由/API/权限/状态矩阵 | 产品、前端、后端确认 |
| P1 | React 工程和 App Shell | 登录、布局、菜单、权限、请求层 | Shell 回归通过 |
| P2 | P0 业务垂直试点 | 需求、任务、缺陷、项目 | 新旧数据和操作一致 |
| P3 | 协同和经营域 | 大事儿、周报、邮件、营收、驾驶舱 | 关键业务回归通过 |
| P4 | 销售和系统域 | 商机、报价、用户、角色、菜单、配置 | 权限和敏感信息通过 |
| P5 | AI 和切换 | AI 助手、连接器、双轨切换 | 生产观察期结束 |

排期按“1 名主前端 + 1 名协作前端/测试”粗估为 10～15 周；实际排期必须以 P0 盘点结果和团队投入重新校准。

## 2. 领域迁移顺序

1. App Shell、登录、权限、动态菜单
2. 需求、任务、缺陷、项目
3. 大事儿、周报、邮件
4. 营收、BU 驾驶舱、KPI
5. 商机、报价策略、报价单
6. 用户、角色、菜单、工作流、配置
7. AI 助手、AI 连接器、生产切换

## 3. 验收门禁

### 功能门禁

- 创建、编辑、删除、查询和详情必须改变真实后端状态。
- API 参数、权限、分页、状态语义与旧版本一致。
- 云效对象保持只读，敏感配置不回显。
- 导入、导出和下载文件可真实完成。

### UI/UE 门禁

- 320、390、768、1024、1280、1440 宽度无页面根横向溢出。
- 核心流程支持键盘完成，focus-visible 清晰。
- Loading、Empty、Error、Disabled、Saving、Success 状态齐全。
- 颜色对比度达到 4.5:1。
- 动效遵守 `prefers-reduced-motion`。

### 工程门禁

- TypeScript 检查通过。
- Lint 通过。
- Playwright 核心回归通过。
- 视觉快照无未解释差异。
- 初始 Shell 和业务路由按需分包。
- 新旧前端都有可复现的部署和回滚方式。

## 4. 切换与回滚

- 新前端先使用独立路径或独立域名部署。
- 每个业务域单独配置启用开关。
- 切换前保存旧版本构建产物和部署版本号。
- 生产观察期内保留旧路由回退入口。
- 出现数据口径、权限或写入异常时立即回退，不等待视觉问题修复。
