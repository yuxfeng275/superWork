# T01 功能基线与契约冻结

## 目标

建立“功能不变”的可执行事实底稿，明确每个路由的 API、权限、状态、写入行为和回归证据。

## 责任

- Owner：前端负责人
- 协作：产品、后端、测试、业务域负责人

## 工作项

1. 从 `frontend/src/router/index.ts` 导出完整路由表。
2. 为每个页面记录页面目标、角色、入口、深链和离开行为。
3. 从 `frontend/src/utils/api.ts` 建立按业务域的 API 清单。
4. 标记所有写操作、导入、导出、下载和流式接口。
5. 读取 `.trellis/spec/frontend/` 中的业务 UI 合约。
6. 将现有 25 个 Playwright 用例映射到页面和业务契约。
7. 记录 loading、empty、error、disabled、permission denied 状态。
8. 记录敏感数据遮罩和只读边界。
9. 生成新旧路由映射表和迁移优先级。

## 输出物

- `route-api-permission-matrix.md`
- `functional-invariants.md`
- `e2e-baseline.md`
- `migration-priority.md`

## 验收标准

- 28 个页面全部有记录。
- 关键 API 写操作全部有明确的最终状态验证方式。
- 权限和敏感信息规则无“待确认”项，或明确标注责任人和截止时间。
- 每个 P0 页面至少有一条可执行回归用例。

## 失败返回条件

- 页面或接口无法找到事实来源时，停止迁移并返回补充审计。
- 后端接口语义仍在变化时，标记为 `blocked`，不在新前端复制临时逻辑。
