# T05 需求、任务、缺陷、项目垂直试点

## 目标

用典型业务验证新架构能否保持功能不变，同时显著改善信息层级和操作效率。

## 迁移范围

- `/requirements`
- `/requirements-standalone/:id`
- `/tasks`
- `/defects`
- `/projects`

## 工作项

1. 建立 requirements、tasks、defects、projects API adapter。
2. 建立服务端分页、筛选、排序和 query cache。
3. 将需求页拆分为列表、筛选、分析、详情和流程动作。
4. 保留云效来源标签和云效任务只读规则。
5. 将任务和缺陷分别呈现，不合并成泛化工作项页。
6. 迁移新建需求、任务和项目表单。
7. 迁移详情抽屉和独立详情路由。
8. 迁移移动端卡片和表格容器滚动。
9. 迁移并扩展现有 Playwright 用例。
10. 对比新旧页面请求参数和最终数据状态。

## 验收标准

- 需求、任务、缺陷、项目核心 CRUD 闭环通过。
- 绑定云效需求不重复渲染。
- Yunxiao task 无本地编辑入口，不能请求 undefined ID。
- 320px/390px 无页面根横向溢出。
- 视觉评审和业务负责人验收均通过。
