## 2. 目录结构

```text
frontend-react/
├── config/
├── src/
│   ├── app/                 # providers、routes、access
│   ├── layouts/             # AppLayout、AuthLayout、StandaloneLayout
│   ├── design-system/       # token、主题、业务模式组件
│   ├── services/            # 按领域拆分的 API adapter
│   ├── features/            # 按业务域组织页面和交互
│   ├── components/          # 跨业务共享组件
│   ├── hooks/               # 查询、权限、键盘和响应式 hooks
│   ├── types/               # contracts、view models、guards
│   └── utils/
└── tests/
```

## 3. 服务端状态和请求边界

- `services/http` 负责 Base URL、Token、401、错误归一化和超时。
- `services/<domain>` 负责接口路径、参数、响应解包和类型。
- React Query 负责查询缓存、失效、请求竞态和重试策略。
- Feature 页面只使用领域 hook，不直接构造 `fetch`。
- 写操作完成后必须明确刷新哪些 query，不能只更新本地 Toast。

### 统一交互模式

- 顶部为“页面标题 + 范围 + 核心指标 + 主操作”的决策型页面头部。
- 详情优先使用保持列表上下文的宽抽屉。
- 表格统一支持筛选、分页、排序、列配置、加载、空态、错误和批量操作。
- 移动端允许表格在容器内滚动，不允许页面根节点横向溢出。
- 所有可操作控件必须有 hover、focus-visible、disabled 和 loading 状态。
- AI 操作必须显示来源、工具状态、失败原因和人工确认边界。

## 5. 组件使用边界

| 场景 | 目标组件 |
|---|---|
| 全局壳层 | ProLayout / Layout / ConfigProvider |
| 数据列表 | ProTable，复杂场景使用定制 Table |
| 表单 | ProForm，长流程拆 StepForm |
| 详情 | ProDescriptions / Drawer |
| 卡片和摘要 | ProCard / Statistic |
| AI 会话 | Ant Design X |
| 业务特有交互 | 自研 feature 组件，继承统一 token |

不能为了“使用 ProComponents”而强行把营收矩阵、会议展示和复杂时间轴套成普通 ProTable。
