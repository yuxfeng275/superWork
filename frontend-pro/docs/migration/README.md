# SuperWork 前端迁移方案

> **迁移已完成（2026-09-25）**：本工程（frontend-pro）已是唯一前端，生产入口 `:18080`。旧 Vue 工程（`frontend/`）已下线并从仓库删除（回滚备份在 241 `deploy-backups/20260925-130511/`，源码见 git 历史 `1235e37` 之前）。以下为迁移过程的历史记录，其中“旧 Vue 兜底 / 待切换入口”等表述已不再适用。

## 目标与边界

- 只重做前端工程：布局、交互、信息架构、视觉和组件实现可以变化。
- 后端接口、数据库、权限语义、业务状态和已有业务动作保持不变。
- 以生产环境行为为事实基线；页面必须接真实接口，禁止用 mock 或空壳路由冒充完成。
- ~~迁移期间旧 Vue 工程继续作为生产兜底，按页面切片验收后再切换入口。~~（已于 2026-09-25 完成切换并删除旧工程）

## 方案决策

采用“独立 React 工程渐进迁移”，不直接在旧 Vue 工程上大面积重构，也不一次性全量重写后切换。

原因：

1. 现有页面数量多、权限和写操作边界复杂，一次性重写会放大功能遗漏风险。
2. 独立工程可以先建立统一的 Ant Design Pro 6 + ProComponents 组件和视觉基线，再按业务域逐页替换。
3. 每个切片都可以通过真实 API、浏览器行为和旧页面对照验收，失败时可快速回退旧入口。

## 菜单信息架构

菜单不做所有页面平铺，采用业务域分组，并且只展示已完成真实迁移的入口：

```text
工作台 / 基础分类 / 销售管理 / 系统管理 / AI 与协作 / 数据分析
```

后续域按旧系统事实基线逐步补齐：基础分类、销售管理、数据分析、系统。只有域内至少有一个已验收页面时才开放分组；未迁移页面不显示空入口，不通过菜单暗示“已支持”。权限菜单接入前，先保留前端分组结构，再将后端授权树映射为同样的层级。

## 页面迁移验收门槛

每个页面必须完成：

- 路由与登录态：未登录重定向、刷新保持、返回原路径。
- 数据闭环：列表/详情/筛选/分页/空态/加载态/错误态与真实接口一致。
- 操作闭环：保存、生成、确认、发布等写操作必须保留原 API、权限和状态变化。
- 视觉与交互：桌面和窄屏不横向溢出；按钮、表格、抽屉、弹窗有 hover/focus/disabled 状态。
- 证据：TypeScript、开发服务编译、生产构建和 HTTP/真实页面访问；当前开发代理已切换到用户在家中可达的 `100.85.67.82:18080`，写接口默认只做代码和接口契约验证，除非明确安排 UAT，不直接改生产数据。
