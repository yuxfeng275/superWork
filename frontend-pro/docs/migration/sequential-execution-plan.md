# SuperWork 前端分批推进计划

更新时间：2026-09-14

## 执行原则

- 只改前端，不改后端 API、数据库、权限语义和业务口径。
- 每批只处理一个可验收的主题，完成后执行 lint、TypeScript、测试、构建和真实页面检查。
- 先处理会阻断发布或造成误操作的体验问题，再处理视觉统一和细节优化。
- 不把“页面能打开”当作完成；写操作必须保留真实状态变化，并单独安排 UAT。

## 批次顺序

| 批次 | 主题 | 目标 | 状态 |
| --- | --- | --- | --- |
| B0 | 基线与信息架构 | 独立工程、路由映射、分组菜单、真实 API 代理 | 已完成 |
| B1 | 全局 Shell 与可访问性 | 一级菜单 hover/active 对比度、焦点态、减少动效、窄屏基础规则 | 本批完成 |
| B2 | 大事儿管理功能对照 | 登记、周更新、会议、演示、详情、权限与主/子项目口径 | 已完成 |
| B3 | 工作台域体验收口 | 需求/任务/缺陷/周报的筛选、详情、空错加载态和操作反馈统一 | 已完成 |
| B4 | 销售与基础分类收口 | 项目、客户、商机、报价策略、报价单的表单和详情交互统一 | 已完成 |
| B5 | 数据分析收口 | 统计、营收、KPI 的矩阵、抽屉、导入和配置交互统一 | 待执行 |
| B6 | 系统与 AI 收口 | 系统五页、邮件、AI 连接器/助手的权限、反馈、长任务状态统一 | 待执行 |
| B7 | 发布前验收 | 权限矩阵、写操作 UAT、生产切换和回退演练 | 待执行 |

## 本批执行内容（B1）

- 深色侧栏一级菜单 hover/active 状态保持白色文字、图标和箭头。
- 增加全局 `:focus-visible` 可见焦点环，保证键盘操作可识别。
- 增加 `prefers-reduced-motion` 规则，降低系统减少动效偏好下的动画干扰。
- 设计系统文档以现有 SuperWork 蓝色品牌和 AlibabaSans 为准，不引入无关的紫色/橙色品牌方案。

## B3 已执行子项

- 需求卡片视图在接口返回前显示骨架加载，不再把“加载中”误显示为“暂无数据”。
- 需求列表统一兼容 `requirementNo / reqNo / serialNumber` 与 `id / requirementId`，修复真实数据卡片出现 `REQ-undefined` 的问题。
- 需求指标“总需求”在分析字段缺失时回退到分页 `total`，避免列表有数据但指标显示 `—`。

## B4 已执行子项

- 报价策略明细的“必选”字段改为受控开关，并将 UI 布尔值正确转换为后端所需的 `0 / 1`。
- 项目管理搜索框改用语义正确的搜索图标，避免将查看图标误用为搜索提示。
- 报价单操作列保留详情/导出主操作，将状态流转与删除收进“操作”菜单；菜单复用原有状态机，并沿用管理角色门禁，避免操作横向铺开或绕过权限。
- 任务分组视图在接口返回前显示骨架加载，无数据时显示明确空态。
- 缺陷看板在接口返回前显示骨架加载，无数据时显示明确空态。

## B4 验收记录

- 已用登录态浏览器检查 `/business-lines`、`/projects`、`/customers`、`/opportunities`、`/quotation-policies`、`/quotations`，确认分组菜单、真实数据读取和核心筛选/操作入口可渲染。
- 当前 B4 代码与构建门槛通过；生产写操作仍按统一发布门槛单独安排 UAT，不在本批制造测试数据。

## B5 预审记录

- 统计、营收、KPI 登录态浏览器读取到真实指标和矩阵；营收补齐旧版 `/revenue/worktime`、`/revenue/delivery`、`/revenue/import`、`/revenue/pending` 深链接，统一映射到同一 React 页面并由路径驱动分栏，入口仍不在侧栏平铺。

## 大事儿列表优化记录

- 登记视图改为左侧快速筛选栏 + 右侧事项列表，保留全部事项、我的事项、我参与的、项目/负责人快捷筛选、状态/优先级/负责人/项目筛选、交付节点和分页。
- 事项列表保留优先级、状态、项目、说明、进度、负责人、计划完成日期、本周更新状态以及详情/编辑/删除操作；会议视图仍使用原有会议卡片和演示模式。
- 通过登录态浏览器检查登记和会议切换，未改变真实 API、权限或写操作边界。

## 后续每批完成标准

1. 代码：真实 API、类型检查、无新增未授权功能。
2. 交互：loading、empty、error、disabled、hover、focus 状态完整。
3. 验证：`npm run lint`、`npm test -- --run`、`npm run build`、`git diff --check`，并用浏览器检查关键路径。
4. 记录：在本文件和 `README.md` 记录变更、证据和未完成门槛。
